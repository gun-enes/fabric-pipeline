|---|---|
| **Scanner** | ai-vulnerability-scan-deep |
| **File** | code/MgmtDbTest/PostDeployment/Script.PostDeployment1.sql:43 |
| **Rule** | CWE-252 |
| **Severity** | Medium |
| **Root Cause** | The post-deployment failure gate queried `[tSQLt_synapse].[TestInfo]` for `result IN ('failure','error')` but never checked `test_rollback_result`, so a run where the test itself passed but its teardown/rollback procedure threw would report deployment SUCCESS while leaving residual test state in the database. |
| **Fix Applied** | Added `OR [test_rollback_result] = 'failure'` to the existing `IF EXISTS` predicate so any rollback failure also raises the deployment-failure exception. |
| **Confidence** | The `test_rollback_result` column is already written by `tSQLt_synapse.RunAll` and already `SELECT`ed in the same table — this is a one-line predicate addition with no new dependencies. |

**Before:**
```sql
IF EXISTS (
    SELECT 1
    FROM [tSQLt_synapse].[TestInfo]
    WHERE [result] = 'failure' OR [result] = 'error'
)
    THROW 50005, 'There exist failed tests. Please check workflow logs for results', 5;
```
**After:**
```sql
IF EXISTS (
    SELECT 1
    FROM [tSQLt_synapse].[TestInfo]
    WHERE [result] = 'failure' OR [result] = 'error'
       OR [test_rollback_result] = 'failure'
)
    THROW 50005, 'There exist failed tests. Please check workflow logs for results', 5;
```
